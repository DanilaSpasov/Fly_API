# Проект: Fly API

## Описание

Проект предназначен для получения информации о самолетах, находящихся в воздушном пространстве выбранной страны.

Программа использует два внешних сервиса:

* `Nominatim OpenStreetMap` — возвращает географические границы страны;
* `OpenSky Network` — возвращает информацию о самолетах внутри полученных границ.

В проекте реализованы:

* абстрактный класс для работы с API;
* получение координат страны через Nominatim;
* получение данных о самолетах через OpenSky;
* модель самолета с валидацией и инкапсуляцией данных;
* преобразование ответа OpenSky в список объектов;
* сравнение самолетов по скорости и высоте;
* абстрактный класс для работы с хранилищами;
* сохранение, получение, фильтрация и удаление данных в JSON-файле;
* получение топа самолетов по высоте полета;
* фильтрация самолетов по нескольким странам регистрации;
* взаимодействие с пользователем через консоль;
* документация классов и функций с помощью докстрингов;
* тестирование основных сценариев работы программы.

## Абстрактный класс AbstractAPI

Класс `AbstractAPI` определяет общий интерфейс для классов, работающих с внешними API.

Класс наследуется от `ABC`, а его методы отмечены декоратором `@abstractmethod`. Благодаря этому каждый наследник обязан реализовать получение границ страны и информации о самолетах.

### Абстрактные методы

* `get_country_bounds(country)` — получает границы указанной страны;
* `get_aeroplanes(country)` — получает информацию о самолетах над указанной страной.

Создать объект `AbstractAPI` напрямую нельзя, поскольку его методы являются абстрактными. Конкретная реализация этих методов находится в классе `AeroplanesAPI`.

## Класс AeroplanesAPI

Класс `AeroplanesAPI` наследуется от `AbstractAPI` и реализует работу с Nominatim и OpenSky.

### Метод get_country_bounds

Метод принимает название страны и отправляет GET-запрос к Nominatim.

Из ответа извлекается поле `boundingbox`, содержащее координаты в следующем порядке:

```
[юг, север, запад, восток]
```

Для запроса к OpenSky координаты преобразуются в порядок:

```
(lamin, lomin, lamax, lomax)
```

Если страна или ее координаты не найдены, метод вызывает `ValueError` с понятным сообщением.

### Метод get_aeroplanes

Метод получает границы страны с помощью `get_country_bounds()` и передает их в OpenSky.

Из ответа OpenSky извлекается поле `states`. Если сервис не вернул самолеты, метод возвращает пустой список.

В HTTP-запросах используются:

* ограничение времени ожидания `timeout=10`;
* проверка HTTP-статуса через `raise_for_status()`;
* обязательный заголовок `User-Agent` для Nominatim.

## Класс Aeroplane

Класс `Aeroplane` описывает один самолет, полученный из ответа OpenSky.

### Атрибуты экземпляра

* `icao24` — уникальный код транспондера самолета;
* `callsign` — позывной;
* `origin_country` — страна регистрации;
* `on_ground` — признак нахождения самолета на земле.

### Приватные атрибуты

* `__altitude` — барометрическая высота в метрах;
* `__velocity` — скорость относительно земли в метрах в секунду.

Доступ к приватным атрибутам выполняется через свойства `altitude` и `velocity`.

### Валидация

При создании объекта класс проверяет:

* высота и скорость должны быть числами;
* логические значения не принимаются вместо чисел;
* скорость не может быть отрицательной.

При нарушении типа вызывается `TypeError`, а при отрицательной скорости — `ValueError`.

### Реализованные методы

* `is_faster_than(other)` — сравнивает два самолета по скорости;
* `is_higher_than(other)` — сравнивает два самолета по высоте;
* `from_state(data)` — создает один объект из строки ответа OpenSky;
* `cast_to_object_list(data)` — преобразует список строк OpenSky в список объектов;
* `__str__()` — возвращает человекочитаемое описание самолета.

При преобразовании данных:

* записи без высоты или скорости пропускаются;
* слишком короткие записи пропускаются;
* отсутствующий позывной заменяется на `Неизвестно`;
* пробелы вокруг позывного удаляются.

### Формат вывода

```
print(aeroplane)
```

Результат:

```
Позывной: TEST123, страна регистрации: Germany, скорость: 230.0 м/с, высота: 10000.0 м.
```

## Абстрактный класс AbstractStorage

Класс `AbstractStorage` определяет общий интерфейс для классов, работающих с хранилищами данных о самолетах.

Класс наследуется от `ABC`, а его методы отмечены декоратором `@abstractmethod`. Благодаря этому каждый класс-хранилище обязан реализовать добавление, получение и удаление информации о самолетах.

### Абстрактные методы

* `add_aeroplane(aeroplane)` — добавляет информацию о самолете в хранилище;
* `get_aeroplanes(criteria)` — получает все записи или фильтрует их по указанным критериям;
* `delete_aeroplane(icao24)` — удаляет информацию о самолете по идентификатору `icao24`.

Создать объект `AbstractStorage` напрямую нельзя. Конкретная реализация работы с JSON-файлом находится в классе `JSONSaver`.

---

## Класс JSONSaver

Класс `JSONSaver` наследуется от `AbstractStorage` и сохраняет информацию о самолетах в JSON-файле.

Путь к файлу передается при создании объекта:

```
json_saver = JSONSaver("aeroplanes.json")
```

### Реализованный функционал

* чтение списка самолетов из JSON-файла;
* добавление объекта `Aeroplane` в файл;
* получение всех сохраненных записей;
* фильтрация записей по одному или нескольким критериям;
* удаление самолета по идентификатору `icao24`;
* сохранение русского текста без преобразования в Unicode-последовательности;
* проверка структуры данных, прочитанных из файла;
* обработка отсутствующего или поврежденного JSON-файла;
* вызов исключения с понятным сообщением при ошибке чтения или записи файла.

### Пример работы с JSON-файлом

```
from src.models import Aeroplane
from src.storage import JSONSaver


aeroplane = Aeroplane(
    "abc123",
    "TEST123",
    "Canada",
    10000.0,
    False,
    230.0,
)

json_saver = JSONSaver("aeroplanes.json")
json_saver.add_aeroplane(aeroplane)

canadian_aeroplanes = json_saver.get_aeroplanes(
    {"origin_country": "Canada"}
)

json_saver.delete_aeroplane(aeroplane.icao24)
```

Если критерии не переданы, метод `get_aeroplanes()` возвращает все сохраненные записи. При передаче нескольких критериев в результат попадают только самолеты, соответствующие каждому из них.

## Функции обработки данных

Функции из модуля `src.utils` работают со списками объектов `Aeroplane` и не зависят от консольного ввода.

### Функция parse_countries

Функция `parse_countries(countries_input)` разделяет введенную строку по запятым, удаляет пробелы по краям названий и пропускает пустые значения.

Пример:

```
countries = parse_countries(
    "Canada, United States, Germany"
)
```

Результат:

```
["Canada", "United States", "Germany"]
```

### Функция filter_aeroplanes_by_countries

Функция `filter_aeroplanes_by_countries(aeroplanes, countries)` возвращает самолеты, зарегистрированные в одной из выбранных стран.

Сравнение названий выполняется без учета регистра. Если список стран пустой, функция возвращает копию полного списка самолетов.

### Функция get_top_aeroplanes_by_altitude

Функция `get_top_aeroplanes_by_altitude(aeroplanes, top_n)` сортирует самолеты по высоте полета в порядке убывания и возвращает первые `N` объектов.

Количество самолетов должно быть положительным целым числом. При неправильном типе вызывается `TypeError`, а при нулевом или отрицательном значении — `ValueError`.

## Консольное взаимодействие

Функция `user_interaction()` объединяет реализованные компоненты в единую программу.

При запуске программа:

* запрашивает страну для поиска самолетов;
* получает информацию через Nominatim и OpenSky;
* преобразует ответ API в список объектов `Aeroplane`;
* сохраняет информацию в файл `aeroplanes.json`;
* запрашивает количество самолетов для топа по высоте;
* запрашивает несколько стран регистрации через запятую;
* выводит топ самолетов и результат фильтрации в человекочитаемом виде.

Пустое название страны, неправильное значение `N`, ошибки API и ошибки записи файла обрабатываются с понятными сообщениями.

Пример ввода:

```
Введите страну для поиска самолетов: Canada
Введите количество самолетов для топа: 5
Введите страны регистрации через запятую: Canada, United States
```

Страна запроса определяет воздушное пространство, в котором выполняется поиск. Страна регистрации самолета может отличаться от страны запроса.

Файл `aeroplanes.json` создается во время работы программы и не добавляется в Git.

## Пример использования

```
from src.api import AeroplanesAPI
from src.models import Aeroplane


api = AeroplanesAPI()
states = api.get_aeroplanes("Canada")
aeroplanes = Aeroplane.cast_to_object_list(states)

for aeroplane in aeroplanes:
    print(aeroplane)
```

## Тестирование

Для проверки проекта используются библиотеки `pytest` и `pytest-cov`.

В проекте реализованы 53 теста. Общее покрытие составляет 90%, что превышает требование задания в 70%.

### API

Проверяются:

* создание абстрактного класса;
* получение координат страны;
* получение данных о самолетах;
* отсутствие страны или координат;
* отсутствие самолетов в ответе;
* обработка ошибки HTTP-запроса.

HTTP-запросы в тестах заменяются с помощью `unittest.mock.patch`, поэтому тесты не зависят от интернета и доступности внешних сервисов.

### Класс Aeroplane

Проверяются:

* создание объекта и значения атрибутов;
* валидация высоты и скорости;
* запрет отрицательной скорости;
* сравнение самолетов по скорости и высоте;
* преобразование ответа OpenSky в объекты;
* обработка отсутствующего позывного;
* человекочитаемое строковое представление.

### JSON-хранилище

Проверяются:

* создание объекта `JSONSaver`;
* добавление самолета;
* получение всех записей;
* фильтрация по критериям;
* удаление по `icao24`;
* отсутствие или повреждение файла;
* ошибки чтения, записи и сериализации.

Для работы с файлами используется фикстура `tmp_path`, поэтому тесты не изменяют рабочий файл `aeroplanes.json`.

### Функции обработки данных

Проверяются:

* преобразование строки в список стран;
* фильтрация по нескольким странам без учета регистра;
